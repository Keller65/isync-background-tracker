# Contrato de Integración y Documentación Técnica: `isync-background-tracker`

## 1. Resumen y Propósito del Módulo
`isync-background-tracker` es un módulo de rastreo en segundo plano de alto rendimiento y optimizado para consumo eficiente de batería en React Native y Expo. Combina almacenamiento local en SQLite (con WAL habilitado), transmisión de datos mediante Protocol Buffers y un motor de geovallas en segundo plano.

---

## 2. Superficie de API Pública (JavaScript / TypeScript)

La librería exporta un objeto principal `BackgroundLocation` con los siguientes métodos nativos disponibles:

* `requestPermissions(): Promise<PermissionResponse>`
  * Pide permisos de ubicación (`Fine`, `Coarse`, `Background`) y notificaciones.
* `start(options: LocationTrackingOptions): Promise<null>`
  * Arranca el servicio en segundo plano (Foreground Service en Android, `CLLocationManager` en iOS).
* `stop(): Promise<null>`
  * Detiene el rastreo y los servicios asociados.
* `getStatus(): Promise<BackgroundLocationStatus>`
  * Retorna si el servicio está activo y disponible.
* `getCurrentLocation(): Promise<LocationEventPayload>`
  * Captura un fix puntual de alta precisión bajo demanda.
* `getMotionState(): Promise<MotionSensorState>`
  * Devuelve el estado actual de los sensores de movimiento por hardware (Significant Motion).
* `addLocationListener(listener: (event: LocationEventPayload) => void): EventSubscription`
  * Escucha en tiempo real los puntos de ubicación aceptados por el pipeline.
* `addGeoVallasListener(listener: (event: GeoVallaEvent) => void): EventSubscription`
  * Escucha las transiciones de entrada y salida de geovallas.
* `getGeoVallas(): Promise<GeoValla[]>`
  * Lee la caché local de geovallas desde la tabla SQLite nativa.
* `refreshGeoVallas(): Promise<GeoValla[]>`
  * Fuerza una descarga fresca del endpoint `/api/geovallas` y actualiza la caché y la base de datos local.
* `setGeovallaNotificationsEnabled(enabled: boolean): Promise<null>` / `getGeovallaNotificationsEnabled(): Promise<boolean>`
  * Controla las notificaciones nativas *heads-up* al entrar en una geovalla.
* `getPendingPoints(limit = 100): Promise<StoredPoint[]>` / `getPendingPointsCount(): Promise<number>` / `deletePoints(ids: number[]): Promise<null>`
  * Gestión directa de los puntos pendientes almacenados en el SQLite local.
* `startBatchSync(): Promise<null>` / `stopBatchSync(): Promise<null>`
  * Controla el drenado durable de puntos pendientes mediante `WorkManager` hacia el endpoint `/gps/batch` vía Protobuf.

## 3. Tipos de Datos Principales (`IsyncBackgroundLocation.types.ts`)

```typescript
export type LocationEventPayload = {
  latitude: number;
  longitude: number;
  accuracy: number;
  altitude: number;
  speed: number;
  heading: number;
  timestamp: number;
};

export type GeoPoint = { latitude: number; longitude: number };

export type GeoValla = {
  id: number;
  nombre: string;
  descripcion: string | null;
  tipo: string | null;
  activo: boolean;
  rings: GeoPoint[][];
  geojson: string | null;
  updated: number;
};

export type GeoVallaEvent = {
  id: number;
  nombre: string;
  tipo: string | null;
  activo: boolean;
  inside: boolean;
  latitude: number;
  longitude: number;
  timestamp: number;
};

export type BackgroundLocationStatus = {
  available: boolean;
  isRunning: boolean;
};

export type LocationTrackingOptions = {
  interval?: number;
  distanceInterval?: number;
  deviceCode?: string;
  deviceName?: string;
  movementConfirmMs?: number;
};

export type MotionSensorState = {
  registered: boolean;
  moving: boolean;
  accelMagnitude: number;
  gyroMagnitude: number;
  magDelta: number;
};

export type StoredPoint = {
  id: number;
  clientUuid: string;
  latitude: number;
  longitude: number;
  altitude: number | null;
  speed: number | null;
  accuracy: number | null;
  heading: number | null;
  timestamp: number;
  sincronizado?: number;
  intentos?: number;
};
